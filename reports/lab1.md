# lab1：多道程序与分时多任务

## 实现

在静态初始化的二维数组中保存每个任务按系统调用编号索引的计数，在系统调用统一入口、分派之前递增当前任务的计数。因此 trace 查询自身次数时包括本次调用；不同任务的统计相互独立。越界的系统调用编号查询返回 -1。计数数组通过 `UPSafeCell` 提供内部可变性，独立于懒初始化的任务控制块，避免将 64 KiB 的计数表作为局部变量搬运。

`sys_trace` 的请求 0 读取指定地址的一个字节；请求 1 将 data 的低八位写入指定地址并返回 0；请求 2 查询当前任务的系统调用次数；其他请求返回 -1。第三章尚未启用用户地址空间隔离，使用直接地址访问。第四章应改为页表翻译并检查 U/R/W 权限。

## 原理与问题分析

- 任务上下文保存内核执行现场，陷阱上下文保存用户寄存器和返回位置，两者用途不同。系统调用将 sepc 加 4，避免返回后重复执行 ecall。
- 协作式切换由 yield 主动触发；抢占式切换由时钟中断触发。二者都先把 Running 任务改为 Ready，再选择下一任务。
- 计数必须放在系统调用统一入口，避免遗漏 exit、yield 和 trace；不能使用全局共享的一份统计，否则会混淆各任务。
- 获取任务管理器的独占访问后，在切换上下文前必须释放借用，避免下一任务再次借用时发生运行时冲突。

## ch3 评测失败后的修正

提供的官方日志显示 `ch3_sleep` 因时间为 0 断言失败，`ch3_sleep1` 和 trace 随后超时，得分为 1/7。`sys_get_time` 的接口仍为写入 `TimeVal { sec, usec }` 并返回 0，与固定版本测试一致；未更改该 ABI。

排查发现旧任务数组为 67,456 字节，已超过 65,536 字节启动栈，更大于 8,192 字节的单任务内核栈。原实现依赖优化器消除初始化时的大数组临时副本。修正将计数表移至直接静态初始化的存储，并只为实际加载的应用创建上下文。在同一套离线兼容依赖和 OpenSBI 下对比：旧代码的 debug 构建在打印内核启动信息后超时；新代码的 debug 与 release 构建均完成 16 个任务的 trace、计时测试。旧 debug 反汇编中可见超过 64 KiB 的初始化栈帧。

补充 `tests/task_stats.rs` 验证计数隔离、非法编号及任务记录大小；QEMU 回归补充非零时间、微秒范围、单调递增以及 yield/忙等待期间的计时推进。可用 `--tasks 16 --mode debug` 复测，默认仍是 release 单任务。
