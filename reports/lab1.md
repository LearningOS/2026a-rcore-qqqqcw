# lab1：多道程序与分时多任务

## 实现

在任务控制块中保存按系统调用编号索引的计数数组，在系统调用统一入口、分派之前递增当前任务的计数。因此 trace 查询自身次数时包括本次调用；不同任务的统计相互独立。越界的系统调用编号查询返回 -1。

`sys_trace` 的请求 0 读取指定地址的一个字节；请求 1 将 data 的低八位写入指定地址并返回 0；请求 2 查询当前任务的系统调用次数；其他请求返回 -1。第三章尚未启用用户地址空间隔离，使用直接地址访问。第四章应改为页表翻译并检查 U/R/W 权限。

## 原理与问题分析

- 任务上下文保存内核执行现场，陷阱上下文保存用户寄存器和返回位置，两者用途不同。系统调用将 sepc 加 4，避免返回后重复执行 ecall。
- 协作式切换由 yield 主动触发；抢占式切换由时钟中断触发。二者都先把 Running 任务改为 Ready，再选择下一任务。
- 计数必须放在系统调用统一入口，避免遗漏 exit、yield 和 trace；不能使用全局共享的一份统计，否则会混淆各任务。
- 获取任务管理器的独占访问后，在切换上下文前必须释放借用，避免下一任务再次借用时发生运行时冲突。

## 验证记录

`cargo fmt --manifest-path os/Cargo.toml -- --check` 与 `git diff --check` 用于格式检查。`tests/trace.rs` 直接包含实际 syscall 源文件，用主机测试验证字节读写、低八位截断及非法请求。

当前环境首次下载官方检查器时网络受限，提权审批服务返回 503；离线构建缺少 riscv Git 依赖。因此尚不能把格式检查或主机测试视为官方评测通过。联网后应执行 `make -C ci-user test CHAPTER=3` 并核对最终退出码及报告检查。
