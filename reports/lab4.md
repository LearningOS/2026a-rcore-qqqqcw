# lab4：文件系统与 I/O

## 实现

fstat 从已打开的 File 对象获取 inode 编号、文件模式和链接数，构造清零保留字段的 Stat，再用经过写权限检查的逐页复制写回用户地址。无效或已关闭的 fd、非文件对象和无效用户缓冲区返回 -1。

linkat 在根目录为现有普通文件添加另一目录项，目标名称已存在、源不存在、名称相同或名称非法时返回 -1。两个名称共享同一个磁盘 inode，内容与 inode 编号一致。

unlinkat 删除指定名称。目录空槽可被 create/link 重用，ls 跳过空槽，避免直接缩小目录 size 后造成块分配元数据不一致。链接数从磁盘根目录的实际目录项计算，不改变 DiskInode 的布局，因此与现有文件系统镜像兼容，并可在重新挂载后恢复正确链接数。

文件系统使用 Weak inode 缓存共享已打开 inode。最后一个名字删除后，仍打开的 inode 可以继续读取和写入，fstat 返回 nlink=0；最终 Arc 句柄关闭时回收数据块和 inode 位图。无打开句柄时，最后一次 unlink 立即回收。缓存只持有 Weak，避免引用环。

同时保留前章的内存映射、spawn、调度与时间系统调用实现，spawn 继承父进程文件描述符表。

## 原理与边界

文件描述符是进程内的句柄；目录项维护名字到 inode 的关系；inode 管理实际数据。硬链接增加名字数量，不复制文件内容。unlink 删除名字不应等同于清空共享内容，只有最后一个链接与最后一个打开引用都消失后才能释放对象。

fs 锁串行化命名空间修改，缓存块锁只覆盖必要的磁盘字段操作；需要在不持有同一锁的情况下触发最终引用析构，避免嵌套加锁。
